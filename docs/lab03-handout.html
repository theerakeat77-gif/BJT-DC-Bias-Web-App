03 / Engineering model

อินพุตและสมการที่ใช้

ทั้งสามวงจรเป็น NPN Common Emitter งานนี้ใช้แบบจำลอง DC ที่ประมาณว่า β และ VBE คงที่ในย่าน Forward Active ทุกโหมดรับ VCC, RC, β และ VBE เหมือนกัน

โหมดอินพุตเพิ่มตำแหน่งตัวต้านทาน
Fixed BiasRBRB ต่อจาก VCC ไป Base และ Emitter ต่อลงกราวด์โดยตรง
Emitter BiasRB, RERB ต่อจาก VCC ไป Base และ RE ต่อจาก Emitter ลงกราวด์
Voltage Divider BiasR1, R2, RER1 ต่อจาก VCC ไป Base, R2 ต่อจาก Base ลงกราวด์ และ RE ต่อจาก Emitter ลงกราวด์

หากระแสฐาน IB ตามวงจรที่เลือก

Fixed · IB = (VCC − VBE) / RB
Emitter · IB = (VCC − VBE) / [RB + (β + 1)RE]
Divider · IB = (VTH − VBE) / [RTH + (β + 1)RE]
VTH = VCCR2 / (R1 + R2) และ RTH = R1R2 / (R1 + R2)

หาค่าอื่นจาก IB

IC = βIB   และ   IE = (β + 1)IB
VE = IERE สำหรับ Emitter และ Divider   ส่วน Fixed ใช้ VE = 0 V
VB = VE + VBE   ·   VC = VCC − ICRC   ·   VCE = VC − VE

คำนวณด้วย Ω และ A แล้วแสดง VB, VE, VC, VCE เป็น V และ IC เป็น mA ถ้าฟอร์มใช้ kΩ ให้แปลงเป็น Ω ที่จุดรับข้อมูลครั้งเดียว เช่น 1 MΩ = 1,000 kΩ = 1,000,000 Ω

อย่าสับสนระหว่างอินพุตผิดกับแบบจำลองใช้ไม่ได้ ถ้ากรอกค่าไม่ครบ ไม่ใช่ตัวเลข ไม่เป็นจำนวนจำกัด หรือค่าที่ต้องเป็นบวก ≤ 0 ให้แสดงข้อผิดพลาด ถ้าอินพุตถูกต้องแต่ IB ที่คำนวณได้ ≤ 0 หรือ VCE ≤ 0.2 V ให้เตือนว่าแบบจำลอง Forward Active อาจใช้ไม่ได้ ไม่ต้องหาค่าที่ถูกต้องใน Cutoff หรือ Saturation ใน Lab นี้

04 / Build

ให้ AI พัฒนาโค้ด แล้วตรวจสิ่งที่เปลี่ยน

  1. วางแผนก่อนแก้ ใช้ OpenCode และ Superpowers จาก Lab 2 ให้ AI ชี้ไฟล์และฟังก์ชันเดิมที่ใช้ซ้ำ ตรวจแผนสั้น ๆ ก่อนอนุญาตให้แก้ ห้ามย้ายสมการไปไว้ใน HTML หรือสร้างระบบใหม่ทั้งโปรเจกต์
  2. โมดูลคำนวณ ใน dc_bias.py หรือไฟล์ที่ทำหน้าที่เดียวกัน ให้ AI เขียนฟังก์ชัน Fixed และ Emitter แยกกันตามสมการในใบงาน และเก็บวิธีคำนวณ Divider เดิม นักศึกษาใช้ความรู้จาก Engineering Electronics ตรวจสมการในโค้ด หน่วย และสัญญาณเตือนเมื่อใช้แบบจำลองไม่ได้ โดยไม่ต้องเขียนหรือเติมฟังก์ชันเอง
  3. ผลลัพธ์แบบเดียวกัน ให้ Flask กับทั้งสามฟังก์ชันตกลงชื่อคีย์และหน่วยร่วมกัน เช่น vb_v, ve_v, vc_v, vce_v, ic_ma และข้อความเตือนถ้ามี ถ้า Lab 2 ใช้ชื่อคีย์อื่นอยู่แล้ว สามารถใช้ชื่อนั้นต่อได้
  4. เลือกฟังก์ชันและตรวจอินพุต ใน app.py ใช้ if / elif เลือกโมเดลตามค่าที่ส่งจากฟอร์ม แปลงหน่วยและตรวจเฉพาะช่องที่จำเป็นของโหมดนั้น โหมดที่ไม่รู้จักต้องแจ้งข้อผิดพลาด ไม่เดาเป็น Divider
  5. ฟอร์มและผลลัพธ์ ใน templates/index.html ให้เลือกโหมดและเห็นช่องที่ใช้เท่านั้น หรือทำให้ช่องที่ไม่เกี่ยวข้องใช้งานไม่ได้ ทำแบบเลือกโหมดแล้วโหลดฟอร์มใหม่ได้ ไม่จำเป็นต้องเพิ่ม JavaScript ให้ผลลัพธ์และข้อผิดพลาดระบุโหมดที่เลือก และอย่าให้ผลรอบก่อนดูเหมือนผลของข้อมูลที่เพิ่งกรอกผิด

ตัวอย่างคำสั่งเริ่มงานกับ OpenCode

ใช้ Superpowers ช่วยอ่านโครง Flask จาก Lab 2 และเสนอแผนสั้น ๆ สำหรับ
เพิ่ม Fixed Bias และ Emitter Bias แบบแหล่งจ่ายเดียว โดยผล Divider เดิมต้องคงเดิม
แยกสมการไว้ใน Python ส่งผลเป็น dict ที่มีชื่อคีย์และหน่วยตรงกัน
ใช้เงื่อนไขเลือกฟังก์ชันและตรวจอินพุตตามโหมด
เสนอไฟล์ที่จะเปลี่ยนแล้วรอให้ผมตรวจแผน เมื่อยืนยันแล้วให้เขียนโค้ดตามสมการในใบงาน
สรุปว่าแต่ละฟังก์ชันใช้สูตรอะไร แปลงหน่วยตรงไหน และส่งผลลัพธ์อะไรให้ผมตรวจ
เก็บ tests เดิมไว้ แต่ไม่ต้องสร้าง unittest ใหม่ งานนี้ตรวจผ่าน Browser โดยใช้ตารางของผม

05 / Connect the browser

MCP คืออะไร และต่อ Playwright กับ OpenCode อย่างไร

MCP (Model Context Protocol) คือมาตรฐานที่ให้แอป AI รู้ว่ามีเครื่องมืออะไร เรียกใช้เครื่องมือนั้น และรับผลกลับมา ใน Lab นี้ OpenCode เป็นแอปที่เอเจนต์ทำงานและมี MCP Client ส่วน Playwright MCP เป็น MCP Server ที่เปิดเครื่องมือควบคุมเบราว์เซอร์ให้เอเจนต์ใช้

Skill บอกขั้นตอนbrowser-acceptance-check กำหนดให้ตรวจกรณีไหนและรายงานหลักฐานอะไร ไม่ได้เปิดเว็บเอง
MCP ทำให้เรียกเครื่องมือได้OpenCode ส่งคำสั่งให้ Playwright MCP เช่น เปิด URL กรอกฟอร์ม หรืออ่านหน้าเว็บ
Flask ยังทำงานเหมือนเดิมเบราว์เซอร์ส่งฟอร์มตามปกติ Flask รับค่าและเรียกฟังก์ชัน Python ไม่ต้องลง Playwright ใน requirements.txt

1. เตรียมเครื่อง

ใช้ Playwright MCP เป็นเส้นทางหลักสำหรับฝึก MCP ก่อนคาบให้ผู้สอนลองบนเครื่องสอนหนึ่งรอบ เปิดโปรเจกต์ Flask เดิมใน OpenCode Desktop ตรวจรุ่นจาก About/Settings และตรวจว่ามี Google Chrome กับ Node.js รุ่น LTS ที่ยังได้รับการสนับสนุน เอกสาร Playwright MCP ระบุ Node.js 18 ขึ้นไป คำสั่งด้านล่างใช้ตรวจว่า Terminal เรียก Node และ npx ได้

node --version
npx --version

ถ้าเพิ่งติดตั้ง Node ให้ปิด–เปิด OpenCode ใหม่เพื่อรับ PATH ที่อัปเดต การเรียกแพ็กเกจครั้งแรกต้องเข้าถึง npm ได้ เครื่องสอนหรือเครื่องห้อง Lab ที่จำกัดการติดตั้งควรเตรียมล่วงหน้า

2. เพิ่ม MCP ในโปรเจกต์

เปิด opencode.json หรือ opencode.jsonc ที่รากโปรเจกต์ Flask ถ้ายังไม่มีให้สร้าง opencode.json เลือกตัวอย่างตามรุ่นเพียงแบบเดียว ถ้าไฟล์เดิมมี Model, Provider, Plugin หรือ MCP ตัวอื่น ให้รวมเฉพาะรายการ playwright เข้ากับโครงเดิม ไม่วางทับทั้งไฟล์

OpenCode V2 · วาง Playwright ใต้ mcp.servers 
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["npx", "-y", "@playwright/mcp@latest", "--browser", "chrome", "--isolated"]
      }
    }
  }
}
OpenCode V1 · วาง Playwright ใต้ mcp โดยตรง 
{
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp@latest", "--browser", "chrome", "--isolated"],
      "enabled": true
    }
  }
}

type: local ให้ OpenCode เริ่ม MCP Server เป็นโปรเซสในเครื่องและสื่อสารผ่าน stdio ไม่ต้องเปิด URL หรือพอร์ตของ MCP เอง พอร์ต 5000 เป็นของ Flask --isolated ใช้โปรไฟล์ทดสอบแยกไว้ในหน่วยความจำ ไม่ใช้เซสชัน Chrome ส่วนตัว ตัวอย่างใช้หน้าต่าง Chrome ที่มองเห็นได้ ถ้าต้องการรันโดยไม่แสดงหน้าต่างให้เติม "--headless" ในอาร์เรย์ command เบราว์เซอร์ยังรันจริงในทั้งสองแบบ

3. ยืนยันทีละชั้นก่อนตรวจ A1–A5

  1. Flask พร้อม ให้ Terminal ที่รัน Flask เปิดค้างไว้ แล้วลองเปิด URL ที่ Flask แสดงด้วยตนเอง ถ้าใช้พอร์ตอื่น ให้ใช้ URL นั้นในทุกคำสั่ง เบราว์เซอร์ที่ MCP เปิดต้องเข้าถึง Flask ได้ โดยเฉพาะเมื่อ OpenCode ทำงานผ่าน WSL, SSH หรือ container
  2. MCP เชื่อมต่อ ปิด–เปิด OpenCode Desktop แล้วเข้าโปรเจกต์เดิม ดูรายการ MCP ในแอป หรือใช้ /mcps ใน OpenCode V2 ที่รองรับ หากมี CLI ให้เปิด Terminal ที่รากโปรเจกต์แล้วรัน opencode mcp list ตรวจว่า playwright แสดงสถานะเชื่อมต่อ ไม่ต้องใช้ CLI ถ้าได้ติดตั้งเฉพาะ Desktop
  3. เอเจนต์ใช้เบราว์เซอร์ได้จริง ให้เอเจนต์ทำตามคำสั่งด้านล่าง ตรวจว่ามีการเรียก Browser Tool และผลที่ตอบอ้างอิงหัวข้อกับช่องที่พบจากหน้าเว็บ สถานะ connected เพียงอย่างเดียวยังไม่ยืนยันว่า Chrome เปิดได้หรือเข้าถึง Flask ได้
ใช้ Playwright MCP เปิด http://127.0.0.1:5000/ แล้วอ่าน browser_snapshot
บอกชื่อหน้าที่เห็นและชื่อช่องอินพุตจริงอย่างน้อย 2 ช่อง พร้อมระบุเครื่องมือที่ใช้
ถ้าเปิดไม่ได้ ให้รายงานข้อผิดพลาดที่เครื่องมือคืนมา อย่าอ่านโค้ดหรือใช้ curl แทน
ถ้าพบปัญหาระหว่างเริ่มใช้งาน
อาการตรวจจุดไหนก่อน
ไม่เห็น Playwright หรือ MCP ต่อไม่ได้ตรวจ V1/V2, ตำแหน่งไฟล์และวงเล็บ JSON ตรวจ npx --version และว่าเครือข่ายเข้าถึง npm ได้ จากนั้นเปิดแอปใหม่
MCP ต่อได้ แต่เปิด Chrome ไม่ได้อ่านข้อความจริงจากเครื่องมือ ตรวจว่า Chrome ติดตั้งใน environment ที่รัน OpenCode ถ้าเครื่องมี Edge ที่รองรับอยู่แล้ว ให้ลองเปลี่ยน chrome เป็น msedge
เปิดเบราว์เซอร์ได้ แต่เปิดเว็บไม่ได้ตรวจว่า Flask ยังรันอยู่และ URL/พอร์ตถูกต้อง ถ้า Browser กับ Flask อยู่ต่าง environment ให้ตรวจว่า Browser เข้าถึง URL ของ Flask ได้
เปิดเว็บได้ แต่ AI หาอินพุตหรือปุ่มไม่เจอให้ขอ Snapshot ใหม่หลังเปลี่ยนโหมด ตรวจ <label for="..."> ว่าตรงกับ id ของช่อง และให้ปุ่มมีข้อความชัดเจน
ถ้าเครื่องของกลุ่มใช้ Playwright MCP ไม่ได้ภายในช่วงทดสอบ ให้บันทึก Playwright MCP เป็น NOT RUN พร้อมเหตุผล แล้วใช้ Browser Tool ที่มีใน OpenCode Desktop รุ่นที่รองรับ หรือทดสอบด้วยมือทันที ใช้กรณี A1–A5 และเกณฑ์ให้คะแนนเดียวกัน แต่ระบุวิธีจริงว่าเป็น Playwright MCP, OpenCode Browser หรือ Manual

06 / Browser acceptance

ให้ AI ทดสอบ Browser ด้วยตารางของนักศึกษา

ก่อนให้ AI รัน ให้ใช้สมการจาก Engineering Electronics คำนวณค่าอ้างอิง IC และ VCE ของโหมดใหม่อย่างน้อยหนึ่งกรณีและระบุหน่วย ใช้เครื่องคิดเลขหรือตารางคำนวณช่วยได้ แล้วเติมค่าคาดหมายที่ตารางระบุให้ครบ ค่าอ้างอิงต้องเป็นอิสระจากโปรแกรมที่กำลังตรวจ

ใช้ร่วมกันใน A1–A5 VCC = 12 V, RC = 2.2 kΩ, β = 100 และ VBE = 0.70 V ป้อนค่าตามหน่วยบนฟอร์ม หากแสดงผลตั้งแต่สองตำแหน่งทศนิยม ให้ใช้เกณฑ์ผลต่างไม่เกิน 0.01 mA สำหรับ IC และ 0.02 V สำหรับ VCE โดยเปรียบเทียบกับค่าอ้างอิงที่ยังไม่ปัดเศษ ถ้าฟอร์มเดิมปัดหยาบกว่า ให้ระบุความละเอียดที่ใช้และตกลงเกณฑ์กับ TA ก่อนรัน

คัดลอกตารางไปที่ docs/validation.md หรือรูปแบบที่ผู้สอนกำหนด แล้วกรอกผลที่เห็นจริงพร้อมหน่วย ระบุวิธีจริงเป็น Playwright MCP, OpenCode Browser หรือ Manual

A1 ถ้า Lab 2 เดิมไม่ตรงกับค่าอ้างอิง ให้บันทึกความต่างและปรึกษา TA ก่อนแก้ ไม่ถือว่าผ่านเพียงเพราะยังได้ค่าผิดเท่าเดิม ส่วน A5 ใช้ข้อความที่ฟอร์มแจ้งหรือข้อความจาก Flask ก็ได้ และยังต้องมีการตรวจอินพุตใน Flask ด้วย

รอบตรวจ A1–A5 ทำอย่างไร

  1. กำหนดผลที่จะใช้ตัดสิน ส่ง URL และตาราง A1–A5 ที่มีค่าคาดหมายกับหน่วยให้ AI ใช้ค่าจากการตรวจสอบของกลุ่ม ไม่ให้ AI สร้างคำตอบอ้างอิงจากโปรแกรมที่กำลังทดสอบ
  2. เปิดหน้าเว็บและอ่านช่องในฟอร์ม เริ่มด้วย browser_navigate และ browser_snapshot Snapshot คือข้อความโครงสร้างของหน้าเว็บ เช่น ชื่อปุ่ม ชื่อช่อง และผลที่อ่านได้ ส่วน Screenshot คือรูปหน้าจอสำหรับเก็บหลักฐาน
  3. เลือกวงจรและส่งค่าผ่านฟอร์มจริง ใช้ browser_select_option กับเมนู Dropdown หรือ browser_click ถ้า UI ใช้ปุ่ม ถ้าสลับโหมดแล้วฟอร์มเปลี่ยน ให้อ่าน Snapshot ใหม่ กรอกข้อมูลด้วย browser_fill_form หรือ browser_type ตามหน่วยบนฟอร์ม แล้วคลิกปุ่มคำนวณ
  4. อ่านผลที่เพิ่งแสดง อ่าน Snapshot หลังส่งฟอร์ม ตรวจว่าโหมดและค่าผลลัพธ์เป็นของกรณีนี้ ไม่ใช่ผลของรอบก่อน เปรียบเทียบตัวเลขและหน่วยตามเกณฑ์ สำหรับ A5 ให้บันทึกข้อความที่แจ้งจริง และระบุว่ามาจากฟอร์มหรือ Flask หากแยกได้ การที่ฟอร์มไม่ยอมส่งยังไม่พิสูจน์ว่า Flask ตรวจค่าแล้ว
  5. รายงานก่อนแก้ แล้วค่อยรันซ้ำ ใช้ PASS เมื่อผลที่เห็นตรงเกณฑ์ FAIL เมื่อได้รันแล้วแต่ผลไม่ตรง และ NOT RUN เมื่อเครื่องมือไม่พร้อม เปิดเว็บไม่ได้ หรือรันไม่ครบจนตรวจผลไม่ได้ แนบข้อความจากหน้าเว็บหรือ browser_take_screenshot อย่างน้อยหนึ่งกรณี ถ้าแก้โค้ดให้บันทึกผลก่อน–หลังและรันกรณีที่ได้รับผลกระทบซ้ำ
ดู A3 → A4 ให้ชัด ก่อนกรอก A4 ยืนยันว่าโหมดยังเป็น Emitter และคง VCC, RB, RC, β, VBE เท่าเดิม เปลี่ยนเฉพาะ RE จาก 1 เป็น 2 kΩ แล้วคลิกคำนวณใหม่ เก็บ IC จากทั้งสองรอบเพื่อเทียบกับทิศทางที่กลุ่มทำนาย หากค่าไม่เปลี่ยน ให้ดูหลักฐานว่าเปลี่ยนช่องถูกและเกิดการส่งฟอร์มจริงหรือไม่ก่อนแก้สมการ

Prompt สำหรับรอบตรวจจริง

ใช้ Playwright MCP ตรวจเว็บ Flask ของกลุ่มที่ http://127.0.0.1:5000/
ถ้ามี browser-acceptance-check ให้โหลดก่อน แล้วใช้ตาราง A1–A5 ที่แนบ
เปิดเว็บ อ่าน Snapshot เลือกโหมด กรอกค่าตามหน่วยบนฟอร์ม แล้วกดคำนวณจริง
หลังเปลี่ยนโหมดหรือส่งฟอร์มให้อ่านหน้าที่เปลี่ยนไป อย่าใช้ผลรอบก่อนแทน
เทียบกับค่าคาดหมายและ tolerance ของกลุ่ม ห้ามใช้ค่าจากโค้ดเป็นคำตอบอ้างอิง
รายงาน ID | วิธีตรวจ | อินพุต | ค่าคาดหมาย | ผลที่เห็นพร้อมหน่วย | สถานะ | หลักฐาน
ถ้าไม่ได้รันผ่าน Browser ให้บอกเหตุผลและรายงาน NOT RUN อย่าใช้ curl หรืออ่านโค้ดแทน
อย่าแก้ไฟล์โปรแกรมก่อนส่งรายงานรอบแรก

ถ้าใช้ OpenCode Browser แทน ให้เปลี่ยนชื่อเครื่องมือใน Prompt หากใช้ Manual ให้กรอกตารางด้วยผลที่กลุ่มเห็นจริง ไม่ต้องให้ AI แต่งหลักฐานแทน

แม่แบบ Skill ของโปรเจกต์ สำหรับผู้สอนหรือกลุ่มที่พร้อมใช้งาน

ผู้สอนอาจแนบข้อความด้านล่างใน starter ของโปรเจกต์ที่เส้นทาง .opencode/skills/browser-acceptance-check/SKILL.md หรือให้นักศึกษาใช้คำสั่งรอบตรวจด้านบนได้ทันที ตัวแม่แบบเป็นคำสั่งให้ AI ไม่ได้ติดตั้งหรือเปิดสิทธิ์ให้ใช้ Browser เอง

---
name: browser-acceptance-check
description: Check a running local BJT bias web app in a real browser using student-provided acceptance cases and expected results.
---

1. Get the running local URL and the student's A1–A5 case table.
   Ask for any missing inputs or expected results before judging a case.
2. Prefer Playwright MCP if connected. Use an available browser tool to
   navigate to the local URL, and name the tool actually used. For each case,
   select the mode, fill the relevant fields and submit. Read the actual
   values, units, visible field states or validation message from the page.
3. Compare observations against the student's expectations and tolerance.
   Report case ID, method, expected result, observed result and PASS or FAIL.
   Mark any unexecuted or unobservable case NOT RUN and explain the blocker.
4. Report evidence from the browser, such as visible result text or a
   screenshot if available. Reading source code or sending an HTTP request
   does not count as running a browser case. Do not edit source files while
   checking. Ask before moving from reporting to fixing.

ให้ผู้สอนลองให้เอเจนต์เปิดเว็บแล้วกรอกหนึ่งกรณีบนเครื่องสอนล่วงหน้า ถ้าแม่แบบไม่ถูกโหลด ให้คัดลอกคำสั่งรอบตรวจไปใช้โดยตรง ยังไม่ต้องเตรียมโค้ดที่จงใจทำผิด

ทวนผลและไล่ข้อมูลหนึ่งรอบ

นักศึกษาเปิดเว็บเองแล้วทำซ้ำอย่างน้อยหนึ่งกรณี ถ้าผลไม่ตรง ให้ไล่ดูค่าที่กรอก → ชื่อฟิลด์ที่ Flask รับ → การแปลงหน่วย → ฟังก์ชันที่ถูกเรียก → ค่าที่แสดง แก้ทีละจุดแล้วรันกรณีที่เกี่ยวข้องซ้ำ ถ้าทุกกรณีผ่าน ให้อธิบายด้วยโค้ดว่าค่า RE ใน A4 เดินทางถึงสมการได้อย่างไร ไม่ต้องสร้างบั๊กเพื่อให้มีอะไรแก้
